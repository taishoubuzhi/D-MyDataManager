# 自动标签（规则）· `auto_tag.rule`

按规则给文件挂标签，**不调用模型**。适合「后缀 / 文件名 / 路径 / 正文关键词」这类一眼能判的规则；
需要模型判断的场合用任务 3 的 `auto_tag`（两个插件冲突，靠清单里的 `conflicts`：都能载入但不能同时启用）。

## 用起来是什么样

* **自动标签页**（侧边栏「自动标签」）：管规则、手动跑一次（带进度与取消）。
* **导入页**：「按规则预填标签」——按规则匹配待导入的文件，把命中的标签填进标签框（导入仍然由你点按钮）。
* **数据管理页**：工具栏「按规则挂标签」给选中的条目批量挂；条目右键菜单给单条挂。

## 规则从哪来

规则的模型、匹配引擎和用户规则文件都在共享库 `lib.autolabel` 里：

* 出厂规则 `plugins/lib.autolabel/data/rules.json`（25 条：按数据类型、后缀、文件名等）；
* 用户规则 `.configs/autolabel.rules.json`（同名 `key` 覆盖出厂，保存时只写与出厂不同的规则）。

**任务 2 与任务 3 共用同一份规则文件**（不另建 `auto_tag.rule.json`）：方案要求「规则方案与任务 3 同源」，
两个插件互斥，同时只会有一个在跑，共用一份才能做到切插件不丢配置。

按后缀给某类文件配默认标签，就是建一条 `field=suffix`、`op=is` 的普通规则（`rules.json` 里
`suffix.pdf`、`suffix.photo` 这些就是），匹配路径和手动写的规则完全一样，所以页面上不再另设一张
「数据格式」表。这一页的规则只用字段匹配，**不调用模型**：编辑到出厂 `prompt.*` 规则时会提示去
会调用模型的那一页改，并禁用保存。

## 文件

| 文件 | 作用 |
| --- | --- |
| `plugin.py` | 清单入口：注册页面，贡献导入页动作、管理页工具栏与条目菜单三个扩展点 |
| `runner.py` | 纯逻辑（不 import Qt）：算标签、按标签分组批量写；`configure_suffix` / `merge_suffixes` 是历史后缀辅助函数，页面已不再调用（保留给测试与外部复用） |
| `ui/page.py` | 「自动标签」配置页与运行面板 |
| `ui/__init__.py` | 界面子包 |

## 边界

* `runner.py` 只读 `app.sdk.items`（`list_items` / `read_text` / `tag_items`），**不直接开会话、不碰界面**；
  界面进度由调用方传 `progress` / `cancel` 回调。
* 「文件内容」字段的规则才会去读正文（`TEXT_LIMIT = 2000` 字），其余规则只看 `ItemRef`，所以批量很快。
* 正文读不出来只记一条提示，不影响其它规则。
* 界面只用集成 UI 工具库（`dm_plugin.builtin.lib.ui`）画，PyQt6 只取 `QTimer` / 布局，
  `qfluentwidgets` 只允许 `FluentIcon`（由自检 `autolabel_ui_via_tool_library` 守着）。
