# 自动关键词（规则）· `auto_keyword.rule`

按规则给文件挂关键词，**不调用模型**。适合「后缀 / 文件名 / 路径 / 正文关键词」这类一眼能判的规则；
要模型读内容提词用 `auto_keyword`（那一页把正文交给模型）。两个关键词插件在清单里互指 `conflicts`，
**都能载入但不能同时启用**：要用规则挂一批、再让模型补其余条目，按顺序换着跑即可。
（与两个标签插件之间没有冲突：产物不同，可以同时启用。）

## 用起来是什么样

* **自动关键词页**（侧边栏「自动关键词（规则）」）：管规则、管关键词库、手动跑一次（带进度与取消）。
* **导入页**：「按规则预填关键词」——按规则匹配待导入的文件，把命中的关键词填进关键词框（导入仍然由你点按钮）。
* **数据管理页**：工具栏「按规则挂关键词」给选中的条目批量挂；条目右键菜单给单条挂。

## 规则从哪来

规则的模型、字段取值与匹配算子都在共享库 `lib.autolabel` 里（`dm_plugin.lib.autolabel.rules`），
本插件只提供数据与界面：

* 出厂规则写在 `store.py` 的 `FACTORY_RULES` 里（9 条：图片 / 视频 / 音频 / 文档 / 表格 / 演示 / 压缩包 / 代码 / 文件名带「截图」），
  不占 `.data/`，所以插件根目录里只有 `plugin.py` / `plugin.json` / `PLUGIN.md` / `.plugin/`；
* 用户规则 `.configs/autolabel.keyword-rules.json`（同名 `key` 覆盖出厂，保存时只写与出厂不同的规则）。

**刻意不和标签那份 `autolabel.rules.json` 共用一个文件**：两边共用同一套规则模型，但标签规则与关键词规则是两回事，
混在一起会互相顶掉。要按后缀挂某类关键词，就是建一条 `field=suffix`、`op=in` 的普通规则（出厂规则就是这么写的）。

## 关键词库

程序本体**没有**关键词库，库是本插件自己的东西，存在 `.configs/autolabel.keywords.json`：

* 手工加：输入框里写一个或多个词（逗号 / 空格 / 顿号分隔），点「加入库」；
* 扫描现有条目：读一遍当前可见条目，把它们身上的关键词数出来（按出现次数排序），新的直接收进库；
* 删除选中：只从库里去掉，不动条目上已有的关键词；
* 改动先在内存里，点「保存关键词库」才落盘；规则弹窗的「关键词库」下拉就是从这份库里取词。

## 文件

| 文件 | 作用 |
| --- | --- |
| `plugin.json` | 清单：依赖共享库与界面工具库、`conflicts: ["auto_keyword"]`、默认不启用（外部插件） |
| `plugin.py` | 清单入口：注册页面，贡献导入页动作、管理页工具栏与条目菜单三个扩展点 |
| `store.py` | 出厂规则 + 关键词库 / 用户规则文件的读写（`app.sdk.storage`，落在 `.configs/`） |
| `runner.py` | 纯逻辑（不 import Qt）：算关键词、按同一组词批量写、扫描现有条目的关键词 |
| `ui/page.py` | 「自动关键词（规则）」页：规则表 + 关键词库 + 运行面板 |
| `ui/__init__.py` | 界面子包 |

## 边界

* `runner.py` 只读 `app.sdk.items`（`list_items` / `read_text` / `add_keywords`），**不直接开会话、不碰界面**；
  界面进度由调用方传 `progress` / `cancel` 回调。
* 「文件内容」字段的规则才会去读正文（`TEXT_LIMIT = 2000` 字），其余规则只看 `ItemRef`，所以批量很快。
* 正文读不出来只记一条提示，不影响其它规则；某一批写库失败只记一条失败，不拖垮整批。
* 界面只用集成 UI 工具库（`dm_plugin.builtin.lib.ui`）画，PyQt6 只取 `QTimer` / 布局，
  `qfluentwidgets` 只允许 `FluentIcon`（由自检 `autolabel_ui_via_tool_library` 守着）。
